# Pulsate React Native example (Expo)

An Expo app showing `@pulsatehq/react-native-sdk` installed through its config
plugin. It configures the SDK, registers listeners, and logs every event it
receives.

This copy is standalone. It depends on the published library, not on Pulsate's
repository.

## Requirements

Node 24.13 or later, Expo SDK 54, JDK 17 for Android, and Xcode 16 with
CocoaPods for iOS. iOS builds need a Mac.

If `prebuild` fails with `Unable to locate the executable cmake`, React Native
could not download its prebuilt Hermes and is building it from source instead.
Retry in a few minutes, or `brew install cmake`.

## Setup

```bash
npm install
```

Installing creates `credentials.local.ts` from the committed template. If you
installed with `--ignore-scripts`, copy `credentials.local.example.ts`
to `credentials.local.ts` yourself — the app cannot build without it. Open it
and paste the 64-character app ID and key from your Pulsate admin. The app runs
without them, but `configure` is skipped and nothing reaches the dashboard.

## Running

The SDK ships native code, so Expo Go cannot run it. You need a development
build:

```bash
npm run prebuild     # expo prebuild --clean, then pod install on macOS
npm run ios
npm run android
```

`prebuild` regenerates `ios/` and `android/` from `app.config.js` and the
Pulsate config plugin. Re-run it after changing either. The plugin is what adds
the notification service extension on iOS and the manifest entries on Android,
so inspecting the generated projects is the fastest way to see what it does.

## How it is put together

`configure` is called once at bootstrap in `App.tsx`, then listeners are
registered from `listeners.ts`, then a session starts. Credentials come from the
gitignored `credentials.local.ts`.

| Path | What it holds |
|---|---|
| `App.tsx` | Bootstrap, configure, and the screen |
| `listeners.ts` | Every SDK event subscription in one place |
| `app.config.js` | Expo config, including the Pulsate plugin entry and bundle identifiers |
| `ios/`, `android/` | Generated by `prebuild`, not committed — inspect them to see what the plugin does |

The plugin is the point of this app. Run `prebuild`, then read the generated
`ios/PulsateNotificationService/` and the Android manifest to see exactly what
it adds on your behalf.

## Change the bundle identifiers before testing push

`app.config.js` ships with Pulsate's own identifiers so it builds out of the
box:

| Platform | Identifier |
|---|---|
| iOS | `pulsate.reactnativesdk.app` |
| Android | `pulsatehq.reactnativesdk.example` |

Push will not reach you on those. Replace both with identifiers registered to
your own Apple and Firebase accounts, then re-run `prebuild`.

## Push

Android needs `google-services.json` next to `app.config.js`. The config reads
it only when the file is present, so prebuild still succeeds without one, and
Android push simply will not deliver. iOS needs a push-enabled provisioning
profile and an APNs key uploaded to Pulsate.

## Notes

`credentials.local.ts` is created by `npm install` and is already listed in
`.gitignore`, along with the `ios/` and `android/` folders that `prebuild`
generates. Keep it that way — it holds your app ID and key.
